# HeroUI fidelity audit

Last updated: 2026-07-29

This is the working checklist for verifying Namespace UIKit against:

- HeroUI Pro React docs `1.0.0-beta.7`
- HeroUI Pro Storybook
- the official HeroUI source and docs snapshot in `.repos/heroui`

The presence of a source file or matching story count is only an inventory check. A component is
`Verified` only after its API, styles, documented examples, accessibility, responsive behavior, and
applicable interaction states have been compared. Those states include rest, hover, focus-visible,
press, selection, disabled, loading, open/close motion, reduced motion, keyboard operation, drag and
drop, resizing, and touch behavior where relevant.

## Status legend

- `⬜ Inventory` — implementation, docs, and stories are present; fidelity is not yet verified.
- `🟨 Gap` — a specific difference is confirmed and recorded in Notes.
- `🛠 Fixed` — a confirmed gap was fixed but still needs final browser verification.
- `✅ Verified` — source/API review and rendered interaction review passed.
- `⛔ Blocked` — upstream behavior could not be accessed or reproduced; the reason is recorded.
